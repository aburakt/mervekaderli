# astro-pb-template

Astro (statik) + PocketBase site şablonu ve ortak çekirdek (core). Standart: `astro-pocketbase` skill'i (ADR-002). Bu repo hem yeni sitenin başlangıcı ("Use this template") hem de mevcut sitelerin `bun run core:sync` ile çektiği ortak dosyaların kaynağıdır.

## Komutlar (bun)
- `bun install` · `bun run check` (astro check) · `bun run build` · `bun test` · `bun run verify`
- `bun run verify`: core + kurallar testi, fixture build, PB build (içerik tohumlanır), **PB/fixture paritesi**, sayfa/başlık/CSP kontrolleri
- `bun run verify` erişilebilirlik (html lang, img alt, tek h1, başlık sırası, a/button adı, form etiketi, tekrarlanan id) ve performans bütçesini (sayfa başına gzip HTML+CSS+JS ≤ 150 KB, en büyük yerel görsel ≤ 400 KB; `site.config.ts` `budget` ile değişir) ölçer.
- CI (core): `bun audit --audit-level=high`; responsive işi Chrome ile (`BUN_CHROME_PATH`, `--no-sandbox --hide-scrollbars`). Dependabot haftalık, gruplu (bun, github-actions).
- `CONTENT_SOURCE=fixture bun run build`: PB olmadan, `site/src/data/content.json` ile önizleme build'i (noindex)
- `bun run new-site -- --id <id> --domain <alan-adı> --name "<Kurum Adı>" [--port N] [--repo aburakt/<repo>]`: "Use this template" sonrası ilk iş; site.js ID, panel adı (yeni migration), PUBLIC_SITE_URL, fixture kurum adı/verify kontrolleri ve `deploy/server` (unit, Caddy, .env şablonu, kurulum listesi). Kurulmuş sitede yalnız `--force` ile. Core değildir (sitede bir kez çalışır).
- `bun run core:sync [etiket|dal]`: sitede ortak dosyaları template'ten günceller; `bun run core:lock`: yalnız bu repoda, core dosyası değişince kilidi yeniler

## Core
- Ortak dosyaların listesi `core.json`, sürümü ve sha256'ları `core.lock`. `tests/core.test.ts` kilitle ölçer; core dosyası sitede elle değiştirilmez, değişiklik burada yapılır.
- Bu repoda core dosyası değişince: `bun run core:lock`, testler, commit; sonra sürüm etiketi (`v1.2.0`) ve her sitede `bun run core:sync v1.2.0` ile PR.
- Siteye özel her şey üç yerde: `pb/pb_hooks/site.js` (ID, CONTENT, FORMS, RULES, LANG), `site.config.ts` (verify sayfa kontrolleri, hook testi kaydı, isteğe bağlı test verisiyle ikinci build: `testSeed`/`testChecks`; tipler `scripts/site-types.ts`), `pb/pb_hooks/panel/labels.json` (panel etiketleri). Gerisi (migration, seed, sayfalar, tasarım) zaten siteye aittir.
- Core dosyaları başında "ORTAK (core)" yazar.
- `scripts/seed-remote.ts` (core): boş canlı PB'ye içeriği SSH tüneliyle yükler. Siteye özel kısım `scripts/seed.ts`'ten gelir: `seed(pb)`, isteğe bağlı `isEmpty(pb)` (varsayılan: settings kaydı yok) ve `fillEmpty(pb)` (dolu PB'de yalnız boş alanlar; yoksa dolu PB reddedilir). Kimlik bilgisi yalnız `PB_ADMIN_EMAIL`/`PB_ADMIN_PASSWORD` ortamından, yazdırılmaz.
- Otomatik güncelleme (core, her sitede): `.github/workflows/core-sync.yml` pazartesi 09:00'da (ya da Actions'tan elle, etiket/dal seçerek) `core:sync` çalıştırır, değişiklik varsa `core-sync` dalından PR açar; CI yeşilse birleştirilir. Yeni sitede kurulum adımı: repo sırrı `CORE_SYNC_TOKEN` (fine-grained PAT, template ve site için Contents/Pull requests/Workflows read-write; Infisical'da saklanır). Sunucuya dağıtım `.github/workflows/deploy.yml` (core) ile: main'de `pb/pb_hooks` ya da `pb/pb_migrations` değişince paket `pbdeploy@<sunucu>`'ya gider, sunucudaki `pb-deploy <id>` (core `deploy/server/pb-deploy.sh`; anahtar `command=` ile o siteye kısıtlı) yedekler, yükler, yeniden başlatır, `/api/health` gelmezse geri alır; yayındaki migration değişmişse reddeder. Kurulum bir kez ajans makinesinden `bash deploy/server/deploy-setup.sh <id>=<sahip>/<repo>` (sır `DEPLOY_SSH_KEY`, değişkenler `DEPLOY_HOST`/`DEPLOY_KNOWN_HOSTS`; yoksa iş atlanır). `.github/workflows/drift.yml` (core) haftalık sunucunun `GET /api/<ID>/core-version` özetini repoyla karşılaştırır, fark varsa issue açar (repo değişkeni `PB_URL`).
- Marka (core: `brand.pb.js`, `lib/brand.js`, `lib/mail.js`, `panel/brand.js`, `site/src/pages/brand/[file].png.ts`): siteye özel değerler `site.js` `BRAND` (name, color, ink, paper: `#rrggbb`, sitenin CSS'iyle aynı; url = PUBLIC_SITE_URL; logo; icon). `site/public/logo.svg` varsa build `/brand/logo-mail.png` (400×80 şeffaf PNG, kenarı kırpılıp ortalanır; Gmail/Outlook SVG göstermez) ve `/brand/logo-panel.png` (kenarı kırpılmış, 112 px yükseklik) üretir, `BRAND.logo` e-posta logosunun tam adresidir; yoksa boş, e-postada ve panelde ad yazıyla görünür. `site/public/favicon.svg` (yoksa `favicon.png`) varsa build `/brand/icon.png` (128×128) üretir, `BRAND.icon` o adrestir ve panel sekme simgesi olur; yoksa boş, sekmede baş harfli rozet (ad kısaltmayla başlıyorsa kısaltma: "EBS Bilgisayar" → EBS) (test ölçer). Panelde logo girişte en çok 56 px, üst çubukta beyaz kutuda 28 px yüksek. `_superusers` e-posta şablonları (parola sıfırlama, OTP, e-posta değişikliği, doğrulama, yeni konumdan giriş) Türkçe ve markalı, her açılışta `lib/mail.js`'ten yazılır: sahibi core'dur, panelden değiştirilen şablon sonraki açılışta geri gelir. Form bildirimi aynı düzende (`mail.layout`). Panel logosu/rengi `/_/extensions.js`'e eklenen `panel/brand.js` ile (PB 0.40 `app.store.mainLogo/headerLogo/favicon`, `--accentColor`); panel CSP'si dış görsele kapalı olduğu için logo ve simge `GET /api/<ID>/brand/logo` (önce logo-panel.png, olmazsa e-posta logosu) ve `/brand/icon` üzerinden gelir. E-posta HTML'indeki satır içi stil sitenin CSP kuralına girmez.
- Operasyon (core, `ops.pb.js`): içerik değişiklikleri `audit_log` koleksiyonuna yazılır (kim, ne, hangi alanlar; 180 gün, core migration `1792000000_core_audit_log.js`, etiketleri `panel/core-labels.json`); hook hataları `lib/report.js` ile GlitchTip'e gider (`GLITCHTIP_DSN` sunucu `.env`'inde; org müşteriye göre değişir, kod bilmez). GlitchTip projesindeki "Claude otomatik düzeltme" webhook alarmı (`http://n8n:5678/webhook/glitchtip?repo=<sahip>/<repo>`, `new-site` yazdırır) hatayı n8n üzerinden "GlitchTip Website hata düzeltici" routine'ine iletir; routine repoyu bu alarmdan okur, düzeltip PR açar, CI yeşilse merge eder. Tarayıcı hataları (core `ErrorTracking.astro` + `lib/error-tracking.ts`, layout `<head>`'inde): DSN siteye ait `site/src/lib/monitoring.ts` (boşsa kapalı, önizlemede ve dev'de kapalı), GlitchTip kökenini build sonunda `pbCsp()` connect-src'ye ekler; `@sentry/browser` site bağımlılığıdır.

## Kurallar
- ZORUNLU (her site, yayından önce): GlitchTip projesinde "Claude otomatik düzeltme" alarmı (n8n adresi, `repo=` ile) ve repo "GlitchTip Website hata düzeltici" routine'inin Repositories listesinde. İkisinden biri eksikse site yayına alınmaz (`deploy/server/README.md` §4, `new-site` adımı).
- Şema yalnızca `pb/pb_migrations/` ile; yayına çıkmış migration dosyası düzenlenmez, ek dosya eklenir.
- Her koleksiyonun beş API kuralı açıkça yazılır. Yazma yalnız superuser (null); okuma `published = true` ile sınırlı ya da (settings gibi taslağı olmayan) herkese açık (test ölçer).
- Her alanda Türkçe `help`, her koleksiyonda `presentable` alan, `hideControls` açık, `users` koleksiyonu yok (test ölçer).
- Yeni içerik koleksiyonu `site.js` CONTENT'e eklenir (yoksa değişiklik siteye yansımaz; test ölçer). Ziyaretçi form kutusu (ör. `form_submissions`) CONTENT'e değil FORMS'a yazılır: ziyaretçi yalnız gönderir, okuma ve yönetim superuser'da. Panel etiketi `labels.json`'a yazılır (test ölçer).
- Formlar (core, `forms.pb.js` + `lib/forms.js`): site.js `FORMS` koleksiyonlarına ziyaretçi gönderimi; honeypot (`website`) dolarsa `status=spam`, `kvkk_consent` alanı varsa zorunlu, `notes` gibi personel alanları temizlenir, bildirim e-postası `settings.form_recipient` ya da `FORM_NOTIFY_TO`'ya (SMTP gerekir), `retentionDays` (varsayılan 365) sonra silinir; ayarlar site.js `FORM_OPTIONS` (çok dilde alıcı `recipientBy: { settings, record }`). `site/integrations/pb-csp.ts` (`pbCsp()`) form varken PB adresini `_headers` `connect-src`'e ekler. Test örnek kaydı gerekirse `site.config.ts` `formSamples`.
- Mağaza isteğe bağlıdır (`docs/shop.md`, core `shop.pb.js` + `lib/shop.js` + `lib/shop-<sağlayıcı>.js`; ayar `site.js` `SHOP`, null ise hook kaydedilmez). Şema `pb/shop/1792200000_shop.js` sitede `pb_migrations/`'a kopyalanır; `products` CONTENT'e, sipariş hiçbir listeye girmez (test ölçer). Fiyat ve stok her zaman sunucudan; stok sipariş durumunu izler (pending/paid/shipped/delivered = ayrılmış). İlk sağlayıcı Shopier (`SHOPIER_API_KEY`/`SHOPIER_API_SECRET` sunucu `.env`), dönüş `/api/<ID>/shop/callback/shopier`. İstemci `site/src/lib/shop.ts`, build ayarı `lib/shop-config.ts`; `pbCsp()` PB'yi connect-src'ye, sağlayıcıyı form-action'a ekler.
- Çok dillilik isteğe bağlıdır (`docs/i18n.md`): PB dil korumaları core (`lib/i18n.js`, `i18n.pb.js`; ayar `site.js` `LANG`, tek dilde hook kaydedilmez), yollar/hreflang `site/src/lib/i18n.ts` (siteye ait). `LANGS`/`DEFAULT_LANG`/`RESERVED_SLUGS` `site.js` `LANG` ile aynı tutulur (test ölçer).
- Hook dosyaları aynı global kapsamı paylaşır ve sırasız yüklenir: `*.pb.js` dosyasında üst düzey ad benzersiz olur (ör. `OPS_SITE`), hook'lar birbirinin sırasına güvenmez.
- Panel Türkçedir: `panel-tr.pb.js`, `/_/extensions.js` isteğine `panel/tr.js` (sözlük) ve `panel/labels.json` ile cevap verir.
- Müşteri kısıtlı superuser'dır (`pb_hooks/lib/guard.js`): `PB_AGENCY_EMAILS`'te olmayan superuser yalnız içerik kayıtlarını ve kendi şifresini düzenler; şema, ayar, yedek, cron ve hesap yönetimi ajansa açık (test ölçer).
- Build'e superuser token'ı verilmez. PB yoksa build kırılır (yalnız `CONTENT_SOURCE=fixture` istisna).
- CSP `style-src 'self'`, `img-src 'self'`: hiçbir yerde `style=` ya da inline script yok; panel görselleri build'de indirilir, WebP'ye çevrilir, gösterildiği genişliğe küçültülür (`Photo.astro`, `lib/image.ts`). Panel editörü HTML'i `lib/sanitize.ts` ile temizlenir.
- Türkçe büyük/küçük harf ortak `lib/tr.ts`'te (core): `lower`, `upper`, `titleCase`, `softCase` (kısaltma listesi parametreyle; `format.ts` yeniden dışa açar). `toLowerCase`/`toUpperCase` İ/ı'yı bozar; kesme işaretinden sonraki ek küçük kalır (`tests/tr.test.ts`).
- Tasarım sektöre uygun seçilir; tek sabit tema, koyu moda otomatik geçiş yok. Yeni tasarım birleştirilmeden önce *.pages.dev önizlemesi gösterilir.
- Yönlendirmeler: build `dist/_redirects` yazar (`site/src/pages/[redirects].ts`): önce `site/src/data/redirects.txt` sabit satırları, sonra panel `redirects` kayıtları. Biçim/tekrar/döngü panelde (`pb_hooks/lib/redirects.js`) ve build'de (`site/src/lib/redirects.ts`) kontrol edilir; ikisi aynı tutulur (test ölçer). `site/public/_redirects` varsa o geçerli olur, panel yönlendirmeleri çalışmaz; birleştirmek için dosya `src/data/redirects.txt`'ye taşınır.
- SEO: ana sayfada Site Ayarları'ndan Organization/LocalBusiness JSON-LD'si (`lib/seo.ts`); `application/ld+json` veri bloğudur, inline betik sayılmaz. Tarihi olan sayfa sitemap `lastmod` için `recordLastmod` çağırır.
- Yasal sayfalar `pages` koleksiyonunda (`/<slug>/`); sayfa altında yalnız yayındakiler görünür. KVKK ve gizlilik/çerez metinleri template'ten taslak gelir; müşterinin hukuk/KVKK danışmanı onaylamadan yayında bırakılmaz.
- Ziyaret istatistiği yalnız Cloudflare Web Analytics (çerezsiz): `settings.cf_analytics_token` doluysa dış betik `static.cloudflareinsights.com/beacon.min.js`; CSP `script-src`/`connect-src` izinleri `_headers`'ta. Başka analitik/çerez eklenirse gizlilik metni güncellenir.
- GEO ve WebMCP (core, `docs/geo-webmcp.md`): siteye ait `site/src/lib/geo.ts` (`geo()`: sayfalar, künye, iletişim bağlantıları, `aiTraining`) varsa build `/llms.txt`, `/llms-full.txt`, `/robots.txt` (AI cevap botları açık, eğitim botları `aiTraining`), `/<yol>/index.md` ve `/webmcp.json` üretir (`lib/llms.ts`, `pages/[geo].*`); layout `<head>`'inde `<Geo path={path} />` markdown eşini ve WebMCP betiğini (`scripts/webmcp.ts`: `document.modelContext`, yedek `navigator.modelContext`; yalnız okuyan araçlar, form göndermez) ekler. Sayfa JSON-LD'si `lib/jsonld.ts` (WebPage/Article/FAQPage/BreadcrumbList), kurum verisi `lib/seo.ts`. `site.config.ts` `checks`'e `...GEO_CHECKS` (scripts/geo-check.ts) eklenir. Formda `toolautosubmit` kullanılmaz. Sitede ayrı robots dosyası tutulmaz.
- Sırlar Infisical'da; repoda yalnızca `.env.example`. `_yedek/` (WP yedeği, kişisel veri) repoya girmez.
